# Weekly Honest Review — 诚实周报生成器

## 核心原则

**绝对诚实 > 情绪舒适。**

你自己写复盘时，大脑会自动美化记忆、淡化失败、夸大成果——这是认知偏差，无法避免。
但 Claude 直接从对话记录中提炼事实，它不会替你找借口，不会帮你粉饰太平。

> 复盘的意义不是让你感觉良好，而是让你看清真相。

## 工作流

### 步骤 1：读取对话记录

找到并读取用户本周（周一至周日，或用户指定的任意时间段）在 Claude Code CLI 中的所有对话。

对话记录通常分布在两个位置：

1. **`~/.claude/claude-code-sessions/`**
   - 包含会话的元数据（标题、时间戳、路径等）
   - JSON 文件，文件名通常是时间戳或会话 ID
   - **注意**：这里的 JSON 里只有会话标题和时间，**不含实际对话内容**

2. **`~/.claude/local-agent-mode-sessions/audit.jsonl`**
   - 包含实际的对话内容（用户输入和 Claude 回复）
   - 以 JSON Lines 格式存储
   - **这是主要内容来源**，不要遗漏

**操作方法**：
- 先列出 `~/.claude/claude-code-sessions/` 下的文件，按时间筛选出本周的会话
- 读取 `~/.claude/local-agent-mode-sessions/audit.jsonl`，解析出本周的对话记录
- 如果还有其他对话来源（如 `~/.claude/` 下的其他子目录），一并读取

**失败处理（重要）**：
如果访问 `~/.claude/` 目录时被拒绝权限（如 sandbox 环境），**不要反复重试**。立即切换到备选方案：
1. 分析当前工作目录的 `git log`（最近一周的提交）
2. 查看最近修改的文件（`git status` 或文件时间戳）
3. 读取当前目录下最近编辑的代码、文档、脚本等文件内容
4. 基于这些实际文件活动还原本周工作内容

**只有当以上所有方法都无法获取任何信息时**，才告知用户无法读取工作记录，并请用户手动提供本周的工作摘要。

### 步骤 2：解析与归类

基于读取到的对话内容，按以下维度进行归类：

**动态分类体系**（根据本周实际内容调整，不强制限定）：
- **产品开发**：写代码、设计架构、修 bug、技术决策
- **内容创作**：写文章、做视频、设计图片、写 newsletter
- **创业探索**：商业模式、市场调研、竞品分析、融资相关
- **工具链**：搭建/优化工作流、写脚本、配置环境
- **投资/财务**：交易、资产配置、财务规划
- **学习成长**：读书、看课、研究新技术
- **沟通协作**：开会、回复邮件、社交互动
- **生活琐事**：非工作类事务（可选，视用户偏好）

**分析维度**：
- 每个类别上投入的大致时间/精力占比
- 每个类别下的关键动作（具体做了什么）
- 哪些对话体现了关键决策或转折点
- 哪些对话暴露了犹豫、反复、拖延

### 步骤 3：生成对内复盘（给自己看的）

这份复盘的核心是**直面真相**，不照顾情绪。

输出格式（Markdown）：

```markdown
# 本周诚实复盘 | YYYY-MM-DD ~ YYYY-MM-DD

## 一句话总结
用一句话概括本周的核心事实。不要修辞，不要比喻。例如：
- "本周 70% 时间花在调一个低级 bug 上，核心功能零进展。"
- "反复换了 3 次技术方案，最终回到第一个。"

## 时间分配（估算）
用列表展示各类别的时间占比。如果某类占比极低但你觉得应该做更多，标注出来。

- 产品开发：X%
- 内容创作：X%
- ...

## 关键决策
列出本周做出的所有重要决定，包括：
- 决定是什么
- 基于什么信息做出的
- 现在看来是否正确（不要事后诸葛亮，但要诚实）

## 完成与未完成

### 实际完成的
只列有明确交付物或明确进展的事项。

### 计划做但没做的
**重点部分**。列出本周计划或提到要做但最终没做的事。
对每一项，诚实分析为什么没做：
- 是真的优先级变了？
- 还是逃避、拖延、完美主义？
- 还是被低优先级事务吞噬了时间？

## 情绪波动（如果有）
从对话中提炼情绪变化：
- 什么时候感到兴奋/自信？
- 什么时候感到焦虑/沮丧？
- 情绪变化是否影响了决策质量？

## 核心反思

### 做得好的（最多 2 条）
不要自我表扬，要基于事实：
- 什么行为产生了实际结果？
- 什么决策被后续对话验证了？

### 做得差的（至少 2 条）
**这是复盘最有价值的部分。**
- 哪些时间被浪费了？怎么浪费的？
- 哪些决策现在看来是错的？
- 哪些反复出现的模式在阻碍进展？
- 是否又在重复之前复盘时指出的问题？（如果是，特别标注）

## 下周聚焦
基于本周的真相，列出下周必须聚焦的 1-3 件事。
不要列 10 条，列多了等于没列。
```

**写作要求**：
- 用第二人称"你"，像一位绝对诚实的朋友在跟你对话
- 可以尖锐，但不要刻薄；要事实，不要讽刺
- 如果某周几乎没做什么有价值的事，直接说"这周很虚"
- 如果反复出现同一个问题，指出并追问"你上次复盘就说过了"

### 步骤 4：生成对外周记（可公开发布的）

基于对内复盘，提炼出 3-5 个有分享价值的话题，写成适合公开发布的内容。

**输出格式**（Markdown）：

```markdown
# 周记 | YYYY-MM-DD ~ YYYY-MM-DD

## 话题 1：[标题]
[200-500 字的分享。可以是一个观察、一个教训、一个思考。]

## 话题 2：[标题]
...

## 话题 3：[标题]
...
```

**内容选择标准**：
- 对读者有启发或参考价值
- 可以失败经历、踩坑记录（读者喜欢这些）
- 不要变成流水账

**敏感信息脱敏规则**（自动推断，严格执行）：
- **财务数字**：具体金额、收益率、仓位比例 → 模糊化或删除
- **未公开项目**：内部代号、未发布产品细节、商业机密 → 泛化处理
- **具体人名**：同事、合作伙伴、投资人真实姓名 → 用角色代替（如"一位投资人朋友"）
- **公司/机构名**：如果涉及敏感合作 → 泛化或隐去
- **具体日期/时间**：如果会暴露未公开信息 → 模糊化
- **负面评价**：对具体人或组织的负面评价 → 删除或改写为抽象讨论
- **任何你觉得发布后可能后悔的内容** → 删除

**语气调整**：
- 对内版是"朋友对你直言不讳"
- 对外版是"你在朋友圈分享思考"
- 保持个人风格，但更加克制和得体

### 步骤 5：交叉验证

使用子代理（subagent）对两份输出进行交叉验证：

**验证 Agent 1 — 事实核查**：
- 对内复盘中的关键事实是否与原始对话记录一致？
- 时间分配估算是否合理？
- 是否有遗漏的重要对话或决策？

**验证 Agent 2 — 敏感信息审查**：
- 对外周记中是否遗漏了需要脱敏的信息？
- 是否有间接暴露敏感信息的风险？（如通过上下文推断）
- 语气是否适合公开发布？

根据验证结果修正两份输出。

## 输出方式

1. **优先将两份输出写入文件**：
   - 对内复盘：`~/weekly-reviews/internal/YYYY-MM-DD.md`
   - 对外周记：`~/weekly-reviews/public/YYYY-MM-DD.md`

2. **同时在对话中展示对内复盘的核心摘要**（对外周记不需要在对话中展示全文，告知用户已保存即可）。

3. 如果用户有指定的输出路径或命名规则，遵从用户偏好。

## 重要提醒

- **不要美化**：用户的默认倾向是自我美化，你要抵消这种倾向
- **不要遗漏失败**：失败和未完成的计划比成功更有复盘价值
- **不要列太多**：聚焦比全面更重要，less is more
- **保持一致性**：如果用户连续使用本 skill，要检查本周是否重复了上周指出的问题
- **尊重用户**：诚实不等于残忍，指出问题时要给出建设性方向
